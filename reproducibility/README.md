# Reproducibility package

[Versión en español](README_ES.md)

This directory documents the external reproducibility package for the ENOE labor-poverty replication project. Large raw and intermediate data files are intentionally kept outside GitHub.

## Expected package contents

```text
ENOE Labor Poverty Replication — Reproducibility Package/
├── Replica_Indice_Pobreza_Laboral.ipynb
├── data/
│   ├── raw/
│   │   ├── zip/
│   │   ├── lpei/
│   │   └── lp/
│   └── parquet/
│       ├── converted/
│       ├── merged/
│       ├── analytical/
│       └── historical/
└── outputs/
    ├── indicators/
    ├── paradata/
    └── validation/
```

## Data roles

- `data/raw/zip/`: official quarterly ENOE source ZIP files.
- `data/raw/lpei/`: poverty-line input used by the calculation pipeline.
- `data/raw/lp/`: official labor-poverty comparison series used for validation.
- `data/parquet/converted/`: normalized SDEM and COE2 Parquet files by quarter.
- `data/parquet/merged/`: person-level SDEM + COE2 merged files.
- `data/parquet/analytical/`: quarterly analytical labor-poverty datasets and quality metadata.
- `data/parquet/historical/`: concatenated person-quarter analytical dataset, manifest, and metadata.
- `outputs/indicators/`: reconstructed quarterly labor-poverty series and associated metadata.
- `outputs/paradata/`: YAML paradata generated by quarter and for historical products.
- `outputs/validation/`: optional saved validation tables or diagnostics.

## Recommended reconstruction order

1. Create a Python environment and install `requirements.txt`.
2. Install or make available the `enoe-utilities` package used by this project.
3. Restore the external reproducibility package with the directory structure shown above.
4. Open `notebooks/Replica_Indice_Pobreza_Laboral.ipynb` from this GitHub repository.
5. Configure project-root paths if the notebook is not executed from the expected working directory.
6. Run the notebook sequentially to convert source files, validate required columns, merge SDEM and COE2, construct analytical files, compute the indicator, build the historical Parquet, and reproduce the statistical validation.

The notebook committed to GitHub should retain its executed outputs so the published results can be reviewed without downloading the full data package.

## Source-data redistribution

Before publicly redistributing original ENOE microdata ZIP files, verify the current INEGI terms and conditions applicable to those files. If direct redistribution is not appropriate, replace the raw files in the public package with a manifest that records, at minimum:

- quarter;
- exact official filename;
- source institution;
- official download page or URL;
- download/access date;
- optional checksum (for example SHA-256).

This preserves reproducibility without implying that the source microdata are authored or redistributed by this project.

## Versioning recommendation

For a stable portfolio release, record:

- Git commit or release tag for this repository;
- Git commit or release tag for `enoe-utilities`;
- Python version;
- dependency versions (`pip freeze` or equivalent);
- exact source-file manifest;
- date on which the official comparison series was downloaded.

## Scope

The external package supports reproduction of the first project stage: historical reconstruction and official-vs-calculated statistical validation. Subsequent exploratory or modeling work can use the historical analytical Parquet as its starting point.
